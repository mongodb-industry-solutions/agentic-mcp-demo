❔ Help — how to drive this demo
Two workflows · Intent-Based Networking (IBN) and What-if scenarios (DTW network digital twin)

The shell is a multi-agent orchestrator. Every query is routed in two stages — a domain classifier picks the demo (IBN or DTW), then Atlas Vector Search picks the MCP service inside that domain — and the matching domain agent runs its own ReAct loop over that domain's tools. Watch the Agent Log on the right to see routing, tool calls and results as they happen, and the Workstreams tab to see the agent's running memory of each thread.

Both opener queries are pre-loaded in the input history: press ↑ once for the IBN opener, twice for the DTW opener. Below, click any prompt to copy it.

1 · Intent-Based Networking

A retail customer asks for connectivity in business language. The agent turns that sentence into a structured intent, checks it against real inventory, activates a plan, then watches it break under load and repairs it.

IBN — intent → feasibility → activation → violation → repair
Services: ibn_intent · ibn_inventory · ibn_feasibility · ibn_assurance · ibn_telemetry_simulator
1

What happens: the IBN agent extracts the fields from free text — site, SLOs, segmentation and timing — and submits a structured intent. The new intent appears on the IBN dashboard immediately (Change Streams).

2

What happens: the intent is matched against sites, resources and topology; geospatial lookup finds nearby spare capacity. You get a verdict with the gaps that block it.

3

What happens: a plan is proposed and then activated — policy snapshots are written and the intent moves to active on the dashboard.

4

What happens: the telemetry simulator pushes a burst of load into the time-series collection, breaching the 40 ms POS latency objective. A compliance violation lights up on the dashboard.

5

What happens — the hero query: one $vectorSearch stage combines semantic similarity over the knowledge base with structured pre-filters on kind, a time window, and a geographic bounding box. Semantics + time + geo + exact match, inside a single index. In ?mode=eng the dashboard shows the raw aggregation pipeline.

6

What happens: the recommended remediation from the retrieved runbook is applied, the template version is bumped, and compliance returns to green.

2 · What-if scenarios (network digital twin)

A digital twin of ACME Mobile's plans, QoS profiles, RAN/core topology and traffic models lives in Atlas. The agent runs simulations against it, so you can ask "what breaks if…" before touching production.

DTW — scenario → refinement → simulation
Services: dtw_plan · dtw_topology · dtw_traffic · dtw_scenario · dtw_simulation
1

What happens: the DTW agent extracts plan, target rate, markets and time window, resolves the numeric rate to the nearest QoS profile (with an explicit substitution note), and creates a what-if scenario. It shows up on the DTW dashboard.

2

What happens: a short follow-up updates the existing scenario in place rather than creating a new one — this is the conversation memory and domain stickiness at work.

3

What happens — the hero query: a $graphLookup walks the dependency tree from the plan through QoS → cells → eNodeBs → SGW → PGW to establish scope, per-cell load is projected from the traffic models, and a hybrid $vectorSearch retrieves analogous past incidents and their mitigations — all in one tool call. Graph for operational structure, vector for institutional memory, one database.

Interleaving the two flows

The two demos are independent: separate domains, separate agents, separate collections, separate workstreams. You can switch between them mid-session and each thread keeps its own state — start the IBN intent, jump to DTW, come back and continue with propose and activate.

One caveat. The short follow-up steps (feasibility check, propose and activate, change to 20 Mbps, diagnose violation, apply runbook, run simulation) carry no domain of their own — they are resolved against the previous turn. If you have just switched demos, name the target explicitly (IBN: feasibility check, DTW: run simulation) so the classifier lands in the right domain. Sequences within one flow are safe to keep short.

Controls in the header

  • ↺ Reset demo data — drops and re-seeds this session's IBN + DTW demo collections and clears the agent-state planes (workstreams, memories, preferences, routing decisions). Shared read-only fixtures and the service/agent catalogue stay put. Use it to get back to a clean slate between runs.
  • 📊 IBN dashboard / 📊 DTW dashboard — open in a second window; both are bound to your session token, so they mirror your own isolated demo lane. Append &mode=exec for the narrative, non-technical rendering, or leave it out for the engineering view with raw pipelines.
  • Agent Log · MCP Servers · Workstreams tabs on the right — live routing/tool trace, the auto-discovered service registry (you can add a new MCP server at runtime), and the agent's per-thread memory.

Typing status or preferences in the shell prints the session's registry state and learned user preferences.
